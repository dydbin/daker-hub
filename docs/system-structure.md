# 시스템 구성

## 서비스명
- Daker Hub

## 시스템 동작 방식
- Daker Hub는 사용자가 웹 페이지에서 해커톤을 탐색하고, 팀 모집글을 작성하거나, 제출 정보를 저장하면 서버가 이를 처리해 공용 데이터와 사용자 상태를 함께 보여주는 구조로 동작한다.
- 화면은 Next.js 기반으로 구성되고, 사용자가 누른 버튼이나 입력한 값은 API 경로를 통해 서버로 전달되며, 서버는 필요한 데이터를 읽거나 저장한 뒤 다시 페이지에 반영한다.

## 구성 요소

### 1. 사용자 화면
- 메인, 해커톤 목록/상세, 팀 모집 보드, 랭킹, 내 페이지 같은 화면이 사용자에게 보이는 프론트 영역이다.
- 사용자는 이 화면에서 탐색, 찜하기, 팀 모집글 작성, 문의 남기기, 제출 저장, Judge Preview 점검 같은 행동을 수행한다.

### 2. 서버 처리
- 서버는 페이지 요청 시 해커톤 정보와 공유 상태를 불러와 화면을 렌더링하고, 사용자의 입력은 API를 통해 받아 처리한다.
- 예를 들어 찜하기, 팀 모집글 생성/수정, 문의 남기기, 제출 저장 같은 동작은 서버를 거쳐 저장소에 반영된다.

### 3. 데이터 저장 구조
- 해커톤 기본 정보와 공개용 사실 데이터는 `data/*.json` 파일에서 읽어 온다.
- 사용자가 생성하는 공유 상태는 Supabase에 저장하며, 여기에는 프로필, 찜한 해커톤, 팀 모집글, 문의 메시지, 제출 개요가 포함된다.
- 이때 운영 비밀값은 서버 환경 변수에만 두고, 심사자는 공개 URL만으로 결과를 확인한다.

### 4. 예외 대응 구조
- Supabase 환경 변수가 없는 경우에는 메모리 기반 fallback으로 동작해 시연용 화면을 유지한다.
- 이 구조 덕분에 배포 환경에서는 실제 공유 상태를 사용할 수 있고, 로컬 확인 환경에서는 최소 기능 검증이 가능하다.

### 5. 배포 구조
- 서비스는 Vercel 배포를 기준으로 구성되어 있으며, Next.js 앱이 서버 렌더링과 API 처리를 담당한다.
- Supabase는 외부 공용 저장소 역할을 맡아 여러 사용자의 상태를 함께 저장하고 불러오는 구조를 만든다.
- 심사자 입장에서는 별도 키 없이 배포 URL만 확인하면 되고, 운영자는 Vercel 환경 변수로만 저장소 연결을 관리한다.

## 한줄 요약
- 정리하면 Daker Hub는 `Next.js 화면 + 서버 API 처리 + Supabase 공유 저장소 + Vercel 배포` 구조로 동작하며, 심사자는 공개 URL만으로 확인 가능한 공개 해커톤 포털이다.
