# Hackathon Evaluation Criteria

이 문서는 사용자 제공 평가 기준을 기준으로 정리한 기준 문서입니다.

## 평가

### 1차 평가
- 최종 제출한 참가팀 및 심사위원 상호 투표평가
- 참가팀 가중치: 30%
- 심사위원 가중치: 70%

### 2차 평가
- 1차 투표평가 상위 10팀에 대해 내부 심사위원 정성평가(100%) 진행

## 내부 심사위원 평가기준

| 평가항목 | 배점 | 평가 포인트 |
| --- | ---: | --- |
| 기본 구현 | 30 | 웹 페이지 구현도, 데이터 기반 렌더링, 필터/정렬 동작, 빈 상태 UI |
| 확장(아이디어) | 30 | 팀 고유 기능/UX 개선의 참신함·실용성, 서비스로서 가치가 드러나는 확장, 일관된 흐름 |
| 완성도 | 25 | 사용성(동선/가독성), 안정성(오류/예외 처리), 성능(로딩/반응성), 접근성/반응형 |
| 문서/설명 | 15 | 기획서의 명확성, PPT의 설계/구현 설명력, 실행/검증 방법(재현성) |

## 동점자 처리 기준
- 심사위원 득표수가 많은 팀이 우선순위
- 팀에게 부여된 투표권 중 사용하지 않은 투표수가 적을수록 우선순위
- 산출물 최초 업로드 시간이 빠를수록 우선순위

## 이 프로젝트에 적용한 해석
- 기본 구현 30점과 완성도 25점을 동시에 가져가기 위해 목록/상세/캠프/랭킹의 동작 안정성을 먼저 확보합니다.
- 확장 30점은 팀 고유 기능 하나를 강하게 세우는 방식으로 대응합니다.
- 문서/설명 15점은 기획서, 웹, PDF가 같은 메시지를 유지하도록 구성합니다.
- 동점자 기준까지 고려하면 제출 패키지는 늦지 않게, 그리고 설명 가능한 상태로 먼저 올리는 것이 유리합니다.
