# Hackathon Rules And Guidelines

이 문서는 사용자 제공 규칙/가이드라인을 기준으로 정리한 기준 문서입니다.

## 규칙

### 제출물
- 기획서(1차 제출)
  - 서비스 개요
  - 페이지 구성
  - 시스템 구성
  - 핵심 기능 명세
  - 주요 사용 흐름
  - 개발 및 개선 계획
- 웹 페이지
- Vercel 배포 URL(필수)
- Github 저장소 링크(필수)
- 솔루션 설명 자료(PDF)
  - PPT로 제작 후, PDF로 변환하여 제출
  - 분량 및 디자인의 제한 없음

### 개발/배포 규칙
- 배포 URL은 외부에서 접속 가능해야 하며 심사 기간 동안 접근 가능해야 합니다.
- 기술 선택은 자유입니다.
- 예시 자료 외 데이터는 제공되지 않습니다.
- 더미 데이터/로컬 저장소(localStorage 등)를 활용해 구현하세요.
- 필요한 정보는 팀이 더미 데이터로 구성하고, 변경 사항은 로컬에 저장되어 유지되도록 구현하면 됩니다.
- 외부 API/외부 DB를 쓰는 경우에도 심사자가 별도 키 없이 확인 가능해야 합니다.
- 키가 필요한 기능은 평가에서 확인이 제한될 수 있습니다.

### 공정성/저작권
- 제출물(코드/이미지/폰트/아이콘 등)은 저작권·라이선스를 준수해야 합니다.
- 타인의 결과물을 무단 복제/도용하거나 라이선스를 위반한 경우 실격 또는 감점될 수 있습니다.
- 팀 내 역할/분업은 자유이며 생성형 AI 도구 사용은 허용합니다.

### 심사 관련 유의사항
- 심사는 기본적으로 배포 URL을 기준으로 진행합니다.
- 확인이 어려운 기능은 심사에서 제외될 수 있습니다.
- 운영진의 추가 안내가 있을 경우 공지 내용이 우선 적용됩니다.

## 이 프로젝트에 적용한 해석
- 배포 대상은 외부 접속 가능한 정적 웹을 우선으로 합니다.
- 로그인, 키 입력, 비공개 API 의존 기능은 핵심 심사 흐름에서 배제합니다.
- 제공되지 않은 데이터는 더미 데이터로 보완하고, 저장은 localStorage 또는 심사자에게 별도 키를 요구하지 않는 외부 저장소 방식으로 설명합니다.
- 제출 패키지는 기획서, 웹링크, PDF가 같은 메시지를 유지하도록 구성합니다.
