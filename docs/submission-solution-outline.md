# Submission Solution Outline

## 1. 프로젝트명
- Daker Hub

## 2. 제출물 3종 공통 첫 문장
- Daker Hub는 해커톤 탐색, 팀 모집, 랭킹, Judge Preview를 한 흐름으로 묶은 공개 해커톤 포털입니다.

## 3. 문제 이해
- 상세 대회 개요는 `docs/hackathon-overview.md`를 기준으로 정리한다.
- 상세 평가 기준은 `docs/hackathon-evaluation.md`를 기준으로 정리한다.
- 기능 명세서만 남겨진 상황에서 빠르게 웹서비스를 구현하고 배포해야 한다.
- 제공 데이터 외 추가 데이터는 없으므로 예시 데이터와 더미 데이터를 활용해야 한다.
- 심사자는 외부에서 접속 가능한 URL로 기능을 확인해야 하며, 별도 키 없이 핵심 흐름을 볼 수 있어야 한다.
- 상세 규칙/가이드라인은 `docs/hackathon-rules-guidelines.md`를 기준으로 정리한다.

## 4. 해결 방향
- Next.js App Router 기반 공개 웹으로 구현해 Vercel 배포와 외부 접근성을 단순화했다.
- `daker.ai/public/hackathons/...` 같은 공개 해커톤 포털 구조를 목표로 메인, 목록, 상세, 캠프, 랭킹 흐름을 구성했다.
- 기획서, 웹 첫 화면, PDF 첫 장에서 같은 문장을 반복해 설명 비용을 낮췄다.
- 제공된 JSON 구조에서 대상 해커톤(`daker-handover-2026-03`)만 선택해 화면에 반영했다.
- 손메모(`memo.png`)와 UI 흐름도(`Hackathon-UI-Flow.png`)를 제품 화면 안에 직접 포함해 구현 근거를 명확히 했다.
- 상세 하단은 보조 데모 대신 공개 금지 목록과 제출 공개 원칙을 명확히 보여주도록 정리했다.
- 심사자는 공개 배포 URL만으로 주요 화면을 확인하고, 운영 비밀값은 서버 환경 변수에만 두도록 정리했다.

## 5. 주요 기능
- 공개 해커톤 메인/목록/상세 포털 UX
- 해커톤 개요, 평가, 공지, 일정, 제출 가이드 표시
- 제출 섹션 옆 테스트 버튼과 별도 분석 화면으로 이어지는 Judge Preview 확장 기능
- 제출 폼을 `프로젝트 제목 / 팀·참가자 / 서비스 개요 / 페이지 구성 / 시스템 구성 / 핵심 기능 명세 / 주요 사용 흐름 / 개발 및 개선 계획` 구조로 통일
- 팀 모집 캠프와 공유 생성/마감 처리
- 팀 모집글별 문의 / 쪽지 스레드
- 전역 랭킹과 기간 필터
- 공개 금지 목록과 제출 공개 원칙 카드
- 공개 URL 확인, 일반 회원가입/로그인, 제출 저장 흐름
- 리더보드 / 팀 데이터 시각화

## 6. 기술 선택
- Next.js App Router
- React
- CSS
- Node.js server runtime
- Supabase
- Vercel

## 7. 데이터 처리 방식
- `public_hackathon_detail.json`의 `extraDetails`에서 대상 해커톤을 선택
- `public_hackathons.json`에서 상태 및 링크 정보 사용
- `public_leaderboard.json`의 `extraLeaderboards` 사용
- `public_teams.json`에서 대상 팀만 필터링
- 읽기용 사실 데이터는 `data/*.json` 더미 데이터로 유지
- 사용자 변경 사항은 서버를 통해 Supabase에 저장하되, 심사자는 별도 키 없이 배포 URL만으로 결과를 확인

## 8. 평가 대응 포인트
- 무키 확인 가능: 별도 API 키, DB 계정, 비밀값 없이 주요 흐름 확인 가능
- 배포 친화적: Vercel에 바로 연결 가능한 Next.js 구조라 외부 URL 구성과 유지가 단순함
- 문제 이해 명확성: 제공 메모와 흐름도를 실제 화면 안에 반영
- 시연 집중도: 첫 화면에서 핵심 가치 1줄, 대표 상태 3개, 데모 진입 1개를 바로 보여준다
- 문서 설명력: Judge Preview와 제출물 3종 공통 첫 문장으로 심사자 설명 비용을 낮춘다
- 보안 분리: 운영용 Supabase 비밀값은 서버 환경 변수에만 두고 제출 자료에는 넣지 않는다

## 10. 향후 개선
- Judge Preview 결과를 PDF 첫 장용 체크 요약으로 자동 정리
- 상세 페이지의 제출/평가/리더보드 영역을 더 강하게 시각 분리
- 수동 QA 체크 결과를 마지막 제출 스냅샷과 함께 저장
