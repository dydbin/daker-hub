# Judge Preview Screen Spec

이 문서는 `Judge Preview`를 화면 단위로 정리한 구현 기준 문서입니다.

## 제품 포지션
- 제품명: Daker Hub
- 확장 기능명: Judge Preview
- 설명: 제출 전에 심사자가 실제로 보게 될 상태를 self-audit 해주는 공개 해커톤 포털 확장 기능

## 화면 1. 홈 `/`

### 화면 목표
- 공개 해커톤 포털이라는 기본 구조를 보여준다.
- 팀 고유 확장 기능인 `Judge Preview`가 제출 흐름 뒤에 연결된다는 점을 이해시킨다.

### 핵심 구성
- 큰 해커톤 카드
- 팀 찾기 / 랭킹 보기 카드
- 각 카드 내부 요약 상태
- 해커톤 상세로 이어지는 명확한 CTA

### 사용 흐름
1. 사용자가 홈에 진입한다.
2. 해커톤을 고르고 상세 페이지로 이동한다.
3. 제출 섹션의 `Judge Preview 테스트` 버튼으로 분석 화면에 들어간다.

## 화면 2. 해커톤 상세 `/hackathons/:slug`

### 화면 목표
- 해커톤 상세 정보와 제출 준비 상태를 한 화면에서 설득한다.
- `Judge Preview`를 제출 직전 self-audit 도구로 사용하게 만든다.

### 핵심 구성
- detail hero
- 섹션 네비
- 개요 / 안내 / 평가 / 일정 / 상금 / 팀
- 제출 섹션
- 리더보드

### Judge Preview 분석 화면에서 보여줄 것
- 총점
- 평가 항목 4개
  - 기본 구현
  - 확장(아이디어)
  - 완성도
  - 문서/설명
- 빠른 체크
  - 문서 필수 구조
  - 팀/참가자 정보
  - 서비스 가치 설명
  - 개발 및 개선 계획
  - 완성도 self-check
  - 공개 금지 정보
- 강점
- 보완 포인트

### 제출 섹션에서 입력받을 것
- 프로젝트 제목
- 팀 / 참가자
- 서비스 개요
- 페이지 구성
- 시스템 구성
- 핵심 기능 명세
- 주요 사용 흐름
- 개발 및 개선 계획
- 구현 self-check
  - 데이터 기반 렌더링
  - 필터/정렬
  - 빈 상태 UI
  - 반응형
  - 오류/예외 처리

### 사용 흐름
1. 사용자가 해커톤 상세를 본다.
2. 제출 섹션에서 입력과 self-check를 채운다.
3. `Judge Preview 테스트` 버튼을 눌러 별도 분석 화면으로 이동한다.
4. 감점 포인트와 보완 우선순위를 확인한다.
5. 제출 섹션으로 돌아와 수정한 뒤 저장한다.

## 구현 원칙
- 확장 기능은 상세의 제출 흐름에서 시작되어야 한다.
- `Judge Preview`는 평가 문서와 규칙 문서를 직접 반영해야 한다.
- 홈과 상세 2개 화면만 압도적으로 polished하게 만든다.
