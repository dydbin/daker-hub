# Daker Hub Final Proposal

## 공통 한 줄 메시지

Daker Hub는 해커톤 탐색, 팀 모집, 랭킹, Judge Preview를 한 흐름으로 묶은 공개 해커톤 포털입니다.

## 1. 서비스 개요

### 서비스명
- Daker Hub

### 한줄 소개
- 해커톤 정보를 찾는 단계부터 팀을 모으고, 참가를 결정하고, 제출 전 준비 상태를 점검하는 단계까지를 하나의 흐름으로 연결한 공개 해커톤 포털입니다.

### 개발 목표
- 흩어진 해커톤 정보를 한 화면 흐름 안에서 탐색하고 비교할 수 있게 합니다.
- 개인 참가, 팀 모집, 팀 문의, 제출 준비를 분리하지 않고 이어지는 사용자 경험으로 정리합니다.
- 제출 전 `Judge Preview` 기반 자가 점검 흐름을 제공해 완성도와 설명력을 높일 수 있게 합니다.

### 타겟 사용자
- 참가할 해커톤을 찾고 비교하려는 예비 참가자
- 팀원이 없지만 먼저 참가를 시작하고 싶은 개인 참가자
- 팀 모집글을 올리고 문의를 관리해야 하는 팀 단위 참가자
- 제출 직전 준비 상태와 부족한 항목을 빠르게 점검하고 싶은 참가팀

### 기대 효과
- 해커톤 탐색, 팀 빌딩, 제출 준비를 한 서비스 안에서 이어서 처리할 수 있습니다.
- 공개 URL만으로 핵심 흐름을 바로 확인할 수 있어 시연 장벽과 진입 장벽을 함께 낮출 수 있습니다.
- 팀 모집과 문의 흐름이 한곳에 모여 협업 시작 속도를 높일 수 있습니다.
- 제출 전 자가 점검 기능으로 누락 항목과 완성도 리스크를 미리 확인할 수 있습니다.

## 2. 문제 정의와 해결 방향

### 문제 정의
- 제공 자료를 바탕으로 빠르게 웹 서비스를 완성해야 하지만, 참가자가 실제로 필요한 흐름은 탐색, 참가 결정, 팀 구성, 제출 준비까지 넓게 이어집니다.
- 심사자는 공개 배포 URL을 기준으로 서비스를 확인하므로, 핵심 기능은 별도 키 없이 외부에서 바로 볼 수 있어야 합니다.
- 단순 정보 나열형 페이지로는 기본 구현 점수는 얻을 수 있어도, 확장성과 서비스 가치가 잘 드러나기 어렵습니다.

### 해결 방향
- Next.js App Router 기반 공개 웹 포털로 구성해 목록, 상세, 팀 모집, 랭킹, 개인 활동 흐름을 하나로 연결했습니다.
- 팀 고유 확장 포인트로 `Judge Preview`를 두어 제출 전 점검 경험을 서비스 가치로 만들었습니다.
- 기획서, 웹, PDF가 같은 첫 문장과 같은 메시지를 공유하도록 설계해 설명 비용을 줄였습니다.
- 운영 비밀값은 서버 환경 변수에만 두고, 심사자는 공개 URL만으로 서비스를 확인하도록 정리했습니다.

## 3. 페이지 구성

### 페이지 간 연결
- `메인(/)`은 전체 서비스의 진입점이며 `Hackathons`, `Camp`, `Ranking`, `MyPage` 흐름으로 이동합니다.
- `해커톤 목록(/hackathons)`에서 특정 대회를 고르면 `해커톤 상세(/hackathons/[slug])`로 이어집니다.
- `해커톤 상세`에서는 대회 확인, 참가 결정, 해커톤별 모집 보드, 제출 저장, `Judge Preview`, 리더보드 흐름이 연결됩니다.
- `Camp(/camp)`는 전체 모집 보드이면서, 특정 해커톤 문맥으로 들어오면 해커톤별 모집 보드로 동작합니다.
- `팀 보드(/camp/board/[teamId])`는 내가 만든 그룹 또는 팀의 모집 상태와 문의를 관리하는 화면입니다.
- `Ranking(/rankings, /rankings/mine)`은 전체 순위와 내 활동 기반 순위를 확인하는 흐름입니다.
- `MyPage(/mypage)`는 찜, 내 그룹/팀 보드, 저장한 제출 개요를 모아 보는 개인 관리 화면입니다.

### 주요 페이지 요약
| 페이지 | 역할 | 핵심 행동 |
| --- | --- | --- |
| `/` | 서비스 전체 요약 진입점 | 대표 해커톤 보기, 캠프/랭킹/내 활동 이동 |
| `/hackathons` | 해커톤 탐색과 비교 | 필터링, 찜하기, 상세 이동 |
| `/hackathons/[slug]` | 참가 판단과 제출 준비 중심 화면 | 대회 신청, 팀 찾기, 제출 저장, Judge Preview 진입 |
| `/hackathons/[slug]/judge-preview` | 제출 전 자가 점검 | 예상 점수 확인, 보완 포인트 확인 |
| `/camp` | 전체/해커톤별 팀 모집 보드 | 팀 만들기, 문의 남기기, 팀 보드 이동 |
| `/camp/board/[teamId]` | 작성자 전용 팀 관리 | 모집 상태 변경, 문의 관리 |
| `/rankings` | 공개 랭킹 확인 | 기간별 비교, 순위 확인 |
| `/rankings/mine` | 내 기준 순위 확인 | 개인화된 랭킹 확인 |
| `/mypage` | 개인 활동 모음 | 찜 목록, 팀 보드, 제출 개요 확인 |
| `/about` | 운영/배포 구조 안내 | 저장 상태, 환경 변수 상태 확인 |

## 4. 시스템 구성

### 전체 구조
- 화면은 Next.js 기반으로 렌더링되며, 사용자의 입력은 API 경로를 통해 서버로 전달됩니다.
- 서버는 해커톤 정보, 팀 모집글, 제출 개요, 개인 활동 상태를 읽고 저장한 뒤 페이지에 반영합니다.
- 읽기용 사실 데이터는 `data/*.json` 에서 불러오고, 사용자 생성 상태는 Supabase에 저장합니다.
- 배포는 Vercel 기준이며, 심사자는 공개 URL만 사용하고 운영 비밀값은 서버 환경 변수에만 둡니다.

### 구성 요소
| 구성 요소 | 역할 |
| --- | --- |
| 사용자 화면 | 해커톤 탐색, 참가 결정, 팀 모집, 제출 저장, 랭킹 확인 |
| 서버/API 처리 | 찜, 팀 모집글 작성/수정, 문의, 제출 저장 등 입력 처리 |
| 데이터 저장소 | 공개 사실 데이터는 JSON, 사용자 상태는 Supabase |
| 예외 대응 | Supabase가 없을 때는 메모리 fallback으로 시연 흐름 유지 |
| 배포 구조 | Vercel 공개 URL 기준 확인, 비밀값은 서버 환경 변수 관리 |

### 한줄 요약
- Daker Hub는 `Next.js 화면 + 서버 API 처리 + Supabase 공유 저장소 + Vercel 배포` 구조로 동작하는 공개 해커톤 포털입니다.

## 5. 핵심 기능 명세

| 기능 | 사용자 입력 | 시스템 동작 | 결과 |
| --- | --- | --- | --- |
| 해커톤 탐색 및 필터링 | 상태 필터, 범위 선택, 태그 검색, 찜하기 | 조건에 맞는 대회를 다시 보여주고 찜 상태를 저장 | 원하는 해커톤을 빠르게 좁혀서 확인 |
| 해커톤 상세 정보 확인 | 특정 해커톤 선택 | 개요, 평가, 일정, 상금, 참가, 제출, 리더보드를 통합 표시 | 참가 여부를 한 페이지에서 판단 |
| 팀 모집글 작성 및 보드 조회 | 팀 만들기, 해커톤 선택, 팀 소개, 모집 포지션, 연락 링크 입력 | 모집글을 저장하고 전체/해커톤별 보드에 반영 | 다른 사용자와 팀 빌딩 시작 |
| 팀 모집글 문의 및 팀 보드 관리 | 문의 메시지 작성, 팀 보드 진입, 보드 설정 수정 | 문의를 owner inbox에 저장하고 작성자 전용 관리 UI 제공 | 공개 문의와 작성자 관리 흐름 분리 |
| 개인 참가 신청 | 대회 신청, 개인으로 바로 신청 | 개인 그룹 상태를 저장하고 중복 등록 방지 | 팀이 없어도 먼저 참가 시작 가능 |
| 제출 개요 저장 | 프로젝트 제목, 서비스 개요, 페이지/시스템/기능/흐름/개선 계획 입력 | 제출 개요를 저장하고 다시 불러오기 가능하게 유지 | 제출 직전 자료를 구조화해 관리 |
| Judge Preview 점검 | `Judge Preview 테스트` 진입 | 저장된 제출 개요를 분석해 예상 점수와 보완 포인트 표시 | 제출 전 부족한 항목을 빠르게 확인 |
| 랭킹 및 내 활동 확인 | 기간 필터, 내 페이지 진입 | 전체 랭킹과 개인 활동 데이터를 요약 표시 | 현재 위치와 다음 행동을 함께 확인 |

### 핵심 차별 포인트
- 단순 해커톤 목록이 아니라 `탐색 -> 참가 결정 -> 팀 빌딩 -> 제출 준비 -> 사전 점검` 이 한 흐름으로 이어집니다.
- `Judge Preview`가 확장 기능으로 들어가 있어, 제출 전 점검이 서비스 가치로 드러납니다.
- 팀 모집 보드와 팀 보드가 분리되어, 공개 탐색과 작성자 관리 경험이 서로 충돌하지 않습니다.

## 6. 주요 사용 흐름

### 대표 사용자 여정
1. 사용자는 메인 페이지에서 대표 해커톤과 주요 진입 버튼을 보고 서비스 구조를 이해합니다.
2. 해커톤 목록에서 필터와 검색으로 원하는 대회를 찾고, 관심 대회는 찜하거나 상세로 이동합니다.
3. 해커톤 상세에서 개요, 평가, 일정, 상금, 참가 방식을 한 번에 확인하고 참가 여부를 결정합니다.
4. 팀이 없으면 개인 참가로 먼저 시작하고, 팀이 필요하면 해커톤별 모집 보드나 전체 모집 보드로 이동합니다.
5. 모집 보드에서 팀을 찾고 문의를 남기거나, 직접 팀 모집글을 작성합니다.
6. 팀 작성자는 팀 보드에서 모집 상태와 문의를 관리합니다.
7. 제출 섹션에서 프로젝트 제목, 서비스 개요, 페이지 구성, 시스템 구성, 핵심 기능 명세, 주요 사용 흐름, 개발 및 개선 계획을 입력해 저장합니다.
8. 저장 후 `Judge Preview`로 이동해 예상 점수와 보완 포인트를 확인하고, 필요하면 다시 수정합니다.
9. 이후 `Ranking` 과 `MyPage` 에서 현재 순위와 저장한 활동을 다시 확인합니다.

### 예외 상황 대응
- 정보 없음:
  조건에 맞는 해커톤이나 모집글이 없으면 빈 상태 문구로 안내하고 다른 필터 시도나 첫 글 작성을 유도합니다.
- 입력 오류:
  필수 입력 누락, 중복, 권한 문제는 같은 화면 안에서 수정 가능한 상태로 유지하고 실패 메시지를 제공합니다.
- 저장소 연결 문제:
  `/about` 에서 현재 저장 상태와 빠진 환경 변수 정보를 확인할 수 있고, 연동이 없을 때는 메모리 fallback으로 시연 흐름을 유지합니다.

| 완성도 25 | 필터/정렬, 빈 상태, 반응형, owner-only 보드 관리, 공개/비공개 흐름을 분리 |
| 문서/설명 15 | 기획서, 웹, PDF가 같은 첫 문장과 같은 구조를 공유하도록 설계 |

### 심사자 확인 방식
- 심사자는 공개 배포 URL만으로 주요 화면을 확인합니다.
- 별도 API 키, DB 계정, 서비스 비밀값 없이 핵심 흐름을 볼 수 있어야 합니다.
- 운영 비밀값은 GitHub, README, 기획서, PDF에 노출하지 않습니다.

## 9. 제출 패키지 정리

### 제출물 간 공통 원칙
- 기획서, 웹, PDF의 첫 문장은 동일하게 유지합니다.
- 제품명은 `Daker Hub` 로 통일합니다.
- 심사자는 공개 URL로 확인하고, 운영 비밀값은 제출물에 넣지 않습니다.

### 제출 직전 입력 항목
- GitHub 저장소 링크: 제출 직전 최신 링크 입력
- Vercel 배포 URL: 제출 직전 최신 URL 입력
- PDF 첫 장 메시지: 본 문서의 공통 한 줄 메시지와 동일하게 유지

## 10. 최종 정리

- Daker Hub는 해커톤 탐색, 팀 모집, 참가 결정, 제출 준비, 사전 점검까지를 끊기지 않는 하나의 서비스 흐름으로 묶는 공개 해커톤 포털입니다.
- 기본 구현 점수와 완성도를 확보하는 구조 위에, `Judge Preview` 라는 팀 고유 확장 포인트를 더해 서비스 가치와 차별성을 보여주는 방향으로 설계했습니다.
- 최종 제출에서는 본 문서를 중심으로 웹과 PDF가 같은 메시지를 유지하도록 구성합니다.
